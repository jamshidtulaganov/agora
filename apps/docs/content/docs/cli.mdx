The Tandem CLI mirrors almost everything the Web UI can do (create [issues](/issues), assign [agents](/agents), start the [daemon](/daemon-runtimes), and more). This page lists every top-level command with a one-line description. For the full set of flags and examples, run `tandem <command> --help`.

## Getting authenticated

Run this the first time you use the CLI to obtain a **personal access token (PAT)**:

```bash
tandem login
```

Your browser opens automatically. After you approve in the web app, the CLI saves the PAT (prefixed with `mul_`) to `~/.tandem/config.json`. Every subsequent command authenticates with that PAT.

<Callout type="tip">
For CI or headless environments, skip the browser flow: create a PAT in the web app under **Settings → Personal Access Tokens**, then run `tandem login --token <mul_...>` to supply it directly.
</Callout>

For the difference between token types, see [Authentication and tokens](/auth-tokens).

## Auth and setup

| Command | Purpose |
|---|---|
| `tandem login` | Log in and save a PAT |
| `tandem auth status` | Show current login status, user, and workspace |
| `tandem auth logout` | Clear the local PAT |
| `tandem setup cloud` | One-shot setup for Tandem Cloud (login + install daemon) |
| `tandem setup self-host` | One-shot setup for a self-hosted backend |

## Workspaces and members

| Command | Purpose |
|---|---|
| `tandem workspace list` | List every workspace you can access |
| `tandem workspace get <slug>` | Show details for one workspace |
| `tandem workspace member list` | List members of the current workspace |
| `tandem workspace update <id> --name "..." [--description "..."] [--context "..."] [--issue-prefix "..."]` | Update workspace metadata (admin/owner). Long fields accept `--description-stdin` / `--context-stdin`. |

## Issues and projects

<Callout type="info">
`list` commands (`tandem issue list`, `autopilot list`, `project list`, etc.) print short, copy-paste-ready IDs by default — issue keys like `MUL-123` for issues, short UUID prefixes for the rest. The `<id>` argument on the follow-up commands below accepts either the short ID or the full UUID, so the typical flow is `tandem issue list` → copy the key → `tandem issue get MUL-123`. Pass `--full-id` to a list command when you need the canonical UUID.
</Callout>

| Command | Purpose |
|---|---|
| `tandem issue list` | List issues (prints copy-paste-ready issue keys) |
| `tandem issue get <id>` | Show a single issue (accepts an issue key or a UUID) |
| `tandem issue create --title "..."` | Create a new issue |
| `tandem issue update <id> ...` | Update an issue (status, priority, assignee, etc.) |
| `tandem issue assign <id> --agent <slug>` | Assign to an agent (triggers a task immediately) |
| `tandem issue status <id> --set <status>` | Shortcut to change status |
| `tandem issue search <query>` | Keyword search |
| `tandem issue runs <id>` | Show agent runs on an issue |
| `tandem issue rerun <id>` | Re-enqueue a fresh task for the issue's current agent assignee |
| `tandem issue comment <id> ...` | Nested: view / post comments |
| `tandem issue subscriber <id> ...` | Nested: subscribe / unsubscribe |
| `tandem project list/get/create/update/delete/status` | Project CRUD |

### Skill import conflicts

`tandem skill import --url <url>` defaults to `--on-conflict fail`. If a skill
with the same name already exists, the command exits with a structured
`conflict` result and does not change the workspace.

Use `--on-conflict overwrite` when you created the existing skill and want to
replace its content while preserving its ID and agent bindings. Use
`--on-conflict rename` to import a copy with an automatic suffix such as `-2`.
Use `--on-conflict skip` to leave the existing skill untouched and report
`skipped`.

```bash
tandem skill import --url https://skills.sh/acme/repo/review-helper
tandem skill import --url https://skills.sh/acme/repo/review-helper --on-conflict overwrite
tandem skill import --url https://skills.sh/acme/repo/review-helper --on-conflict rename
tandem skill import --url https://skills.sh/acme/repo/review-helper --on-conflict skip
```

## Squads

| Command | Purpose |
|---|---|
| `tandem squad list` | List squads in the workspace |
| `tandem squad get <id>` | Show a single squad |
| `tandem squad create --name "..." --leader <agent>` | Create a squad (owner / admin) |
| `tandem squad update <id> ...` | Update name, description, instructions, leader, or avatar |
| `tandem squad delete <id>` | Archive (soft-delete) — transfers assigned issues to the leader |
| `tandem squad member list/add/remove/set-role <squad-id>` | Manage squad members and update roles in place |
| `tandem squad activity <issue-id> <action\|no_action\|failed> --reason "..."` | Used by squad leader agents to record an evaluation per turn |

See [Squads](/squads) for the full model.

## Daemon and runtimes

| Command | Purpose |
|---|---|
| `tandem daemon start` | Start the daemon (background by default; add `--foreground` to run in the foreground) |
| `tandem daemon stop` | Stop the daemon |
| `tandem daemon restart` | Restart the daemon |
| `tandem daemon status` | Check whether the daemon is online and its concurrency |
| `tandem daemon logs` | View daemon logs |
| `tandem runtime list` | List runtimes in the current workspace |
| `tandem runtime usage` | Show resource usage |
| `tandem runtime activity` | Recent activity log |
| `tandem runtime update <id> ...` | Update a runtime's configuration |

## Miscellaneous

| Command | Purpose |
|---|---|
| `tandem repo checkout <url>` | Clone a repo locally for agents to use |
| `tandem config` | View or edit local CLI configuration |
| `tandem version` | Print the CLI version |
| `tandem update` | Upgrade the CLI to the latest release |
| `tandem attachment download <id>` | Download an attachment from an issue or comment |

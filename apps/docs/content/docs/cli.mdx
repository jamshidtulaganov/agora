The Agora CLI mirrors almost everything the Web UI can do (create [issues](/issues), assign [agents](/agents), start the [daemon](/daemon-runtimes), and more). This page lists every top-level command with a one-line description. For the full set of flags and examples, run `agora <command> --help`.

## Getting authenticated

Run this the first time you use the CLI to obtain a **personal access token (PAT)**:

```bash
agora login
```

Your browser opens automatically. After you approve in the web app, the CLI saves the PAT (prefixed with `mul_`) to `~/.agora/config.json`. Every subsequent command authenticates with that PAT.

<Callout type="tip">
For CI or headless environments, skip the browser flow: create a PAT in the web app under **Settings → Personal Access Tokens**, then run `agora login --token <mul_...>` to supply it directly.
</Callout>

For the difference between token types, see [Authentication and tokens](/auth-tokens).

## Auth and setup

| Command | Purpose |
|---|---|
| `agora login` | Log in and save a PAT |
| `agora auth status` | Show current login status, user, and workspace |
| `agora auth logout` | Clear the local PAT |
| `agora setup cloud` | One-shot setup for Agora Cloud (login + install daemon) |
| `agora setup self-host` | One-shot setup for a self-hosted backend |

## Workspaces and members

| Command | Purpose |
|---|---|
| `agora workspace list` | List every workspace you can access |
| `agora workspace get <slug>` | Show details for one workspace |
| `agora workspace member list` | List members of the current workspace |
| `agora workspace update <id> --name "..." [--description "..."] [--context "..."] [--issue-prefix "..."]` | Update workspace metadata (admin/owner). Long fields accept `--description-stdin` / `--context-stdin`. |

## Issues and projects

<Callout type="info">
`list` commands (`agora issue list`, `autopilot list`, `project list`, etc.) print short, copy-paste-ready IDs by default — issue keys like `MUL-123` for issues, short UUID prefixes for the rest. The `<id>` argument on the follow-up commands below accepts either the short ID or the full UUID, so the typical flow is `agora issue list` → copy the key → `agora issue get MUL-123`. Pass `--full-id` to a list command when you need the canonical UUID.
</Callout>

| Command | Purpose |
|---|---|
| `agora issue list` | List issues (prints copy-paste-ready issue keys) |
| `agora issue get <id>` | Show a single issue (accepts an issue key or a UUID) |
| `agora issue create --title "..."` | Create a new issue |
| `agora issue update <id> ...` | Update an issue (status, priority, assignee, etc.) |
| `agora issue assign <id> --agent <slug>` | Assign to an agent (triggers a task immediately) |
| `agora issue status <id> --set <status>` | Shortcut to change status |
| `agora issue search <query>` | Keyword search |
| `agora issue runs <id>` | Show agent runs on an issue |
| `agora issue rerun <id>` | Re-enqueue a fresh task for the issue's current agent assignee |
| `agora issue comment <id> ...` | Nested: view / post comments |
| `agora issue subscriber <id> ...` | Nested: subscribe / unsubscribe |
| `agora project list/get/create/update/delete/status` | Project CRUD |

### Skill import conflicts

`agora skill import --url <url>` defaults to `--on-conflict fail`. If a skill
with the same name already exists, the command exits with a structured
`conflict` result and does not change the workspace.

Use `--on-conflict overwrite` when you created the existing skill and want to
replace its content while preserving its ID and agent bindings. Use
`--on-conflict rename` to import a copy with an automatic suffix such as `-2`.
Use `--on-conflict skip` to leave the existing skill untouched and report
`skipped`.

```bash
agora skill import --url https://skills.sh/acme/repo/review-helper
agora skill import --url https://skills.sh/acme/repo/review-helper --on-conflict overwrite
agora skill import --url https://skills.sh/acme/repo/review-helper --on-conflict rename
agora skill import --url https://skills.sh/acme/repo/review-helper --on-conflict skip
```

## Squads

| Command | Purpose |
|---|---|
| `agora squad list` | List squads in the workspace |
| `agora squad get <id>` | Show a single squad |
| `agora squad create --name "..." --leader <agent>` | Create a squad (owner / admin) |
| `agora squad update <id> ...` | Update name, description, instructions, leader, or avatar |
| `agora squad delete <id>` | Archive (soft-delete) — transfers assigned issues to the leader |
| `agora squad member list/add/remove/set-role <squad-id>` | Manage squad members and update roles in place |
| `agora squad activity <issue-id> <action\|no_action\|failed> --reason "..."` | Used by squad leader agents to record an evaluation per turn |

See [Squads](/squads) for the full model.

## Daemon and runtimes

| Command | Purpose |
|---|---|
| `agora daemon start` | Start the daemon (background by default; add `--foreground` to run in the foreground) |
| `agora daemon stop` | Stop the daemon |
| `agora daemon restart` | Restart the daemon |
| `agora daemon status` | Check whether the daemon is online and its concurrency |
| `agora daemon logs` | View daemon logs |
| `agora runtime list` | List runtimes in the current workspace |
| `agora runtime usage` | Show resource usage |
| `agora runtime activity` | Recent activity log |
| `agora runtime update <id> ...` | Update a runtime's configuration |

## Miscellaneous

| Command | Purpose |
|---|---|
| `agora repo checkout <url>` | Clone a repo locally for agents to use |
| `agora config` | View or edit local CLI configuration |
| `agora version` | Print the CLI version |
| `agora update` | Upgrade the CLI to the latest release |
| `agora attachment download <id>` | Download an attachment from an issue or comment |

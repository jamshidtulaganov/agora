Sales Doctor is a sales-analytics product — dashboards, P&L, and reports for teams across Russian-, Persian-, and Uzbek-speaking markets. The whole thing is built by a small team on a single Agora board, with coding agents working the queue next to the people.

## One board, humans and agents side by side

Every piece of work is an issue: a new dashboard filter, a Stripe billing webhook, an RTL bug in the Persian layout. The assignee field is the same whether a person or an agent picks it up — so a localization fix can go to an agent while a pricing change goes to an engineer, and both show up in the same column.

Agents render with their own avatar and have their own queue. They can be @-mentioned in a thread, reassigned, and they open their own follow-up issues when they hit something out of scope.

---

## What the agents actually do

**Localization.** Right-to-left polish for the Persian UI, alignment fixes for Russian strings like «Общая сумма», and first-pass translations for new screens. The agent reads the i18n conventions once from a shared skill, so every run uses the same glossary instead of re-guessing terms.

**Dashboard features.** Date filters, CSV and PDF export, role-based access — scoped issues an agent can take end to end, opening a pull request the team reviews and merges.

**Billing plumbing.** Stripe webhook handlers and P&L cache rebuilds — the repetitive backend wiring that's easy to specify and easy to verify with tests.

---

## What changed for the team

**Throughput.** A two-workspace team ships like a bigger one. The localization and billing backlog that used to wait for a free engineer now moves in parallel.

**Consistency.** Definitions — how a metric is calculated, which terms to use in each language — live in shared skills, so the output reads the same no matter who (or what) did the work.

**Everything is reviewed.** Agent work lands as a pull request on its issue. A human reads it, requests changes by @-mentioning the agent, and merges when it's right. Nothing ships unseen.

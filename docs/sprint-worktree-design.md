# Sprint Worktree — design + build spec

Worktree-per-task on the shared sprint branch, so N users work one sprint branch in parallel — each with their own co-editor — without disk blowup. Ship behind `AGORA_SPRINT_WORKTREE_ENABLED` (default OFF; the per-task-fork model stays the default, fully reversible).

## Summary
SPRINT WORKTREE plan, grounded in the daemon code. The pivot from today's per-task FORK model to a CI-on-shared-branch model is small and well-precedented: the `CoCodeBranch` mechanism already does exactly what we need at the single-issue level — server resolves a branch name (`coCodeBranchName`), passes it on the claim (`Task.CoCodeBranch`, handler/daemon.go:1340), and the daemon forces every worktree repo onto it before the agent runs (`ensureCoCodeBranch`, daemon.go:2232/2997). Sprint mode = generalize that one branch to a SHARED, REMOTE-TRACKED sprint branch (`SprintBranchFor`, connected_box.go:655 already exists and is the QA/deploy single-source-of-truth), add a fetch+rebase before-work step, symlink shared deps so the working copy is just the source delta, push commits back to the sprint branch instead of opening a per-task PR, and add a TTL prune that never deletes the shared branch. The isolation point that must change is `execenv.PredictRootDir`/`Prepare` (execenv.go:167/188) and the branch-naming in `repocache.CreateWorktree`/`runWorktreeAdd` (cache.go:498/635). N is already bounded by the existing `taskSlotSemaphore`(MaxConcurrentTasks); disk is bounded by symlinked deps + TTL prune of idle per-task subdirs. Ship behind an `AGORA_SPRINT_WORKTREE_ENABLED` flag, sprint-scoped, so the fork model stays the default and the migration is reversible.

Per-task dirs move from {wsRoot}/{wsID}/{shortTaskID}/workdir to {wsRoot}/{wsID}/sprint/{sprintBranchSlug}/{shortTaskID}/workdir, with shared deps installed once at {wsRoot}/{wsID}/sprint/{sprintBranchSlug}/.shared/{repo}/{lockDigest}/ and symlinked into each worktree's node_modules/vendor. Worktrees are created with `git worktree add <path> origin/<sprintBranch>` (DETACHED, no -b) then a local tracking checkout, so 10 worktrees coexist on one branch without the agent/* per-task branch lock that forces uniqueness today.

## Git flow (per task, inside the per-repo lock)
Per task, inside the per-repo lock: (1) CREATE off shared branch — `git -C <bare> fetch origin <sprintBranch>` then `git -C <bare> worktree add <taskDir>/<repo> origin/<sprintBranch>` (detached), then in the worktree `git checkout -B sprint-<branch>-<shortTaskID> origin/<sprintBranch>` and `git branch --set-upstream-to=origin/<sprintBranch>`. (2) PULL-BEFORE-WORK (every claim, before agent runs) — `git fetch origin <sprintBranch>` then `git rebase origin/<sprintBranch>` (on conflict: `git rebase --abort`, warn, annotate sprint_sync_conflict). (3) COMMIT/ACCEPT — `git add -A && git commit -m "..."` then `git push origin HEAD:<sprintBranch>` (NO gh pr create). (4) DISCARD — `git reset --hard origin/<sprintBranch> && git clean -fd`. (5) DONE/TTL — `git -C <bare> worktree remove <taskDir>/<repo>` then `git -C <bare> worktree prune` then `git -C <bare> branch -D sprint-<branch>-<shortTaskID>` (delete ONLY the per-task local alias, NEVER the shared sprint branch and NEVER origin/<sprintBranch>).

## Symlink strategy (the disk bound)
Disk is bounded by sharing dep dirs, not the source tree (source delta per worktree is small; deps are the N× cost). Layout: shared deps live at {wsRoot}/{wsID}/sprint/{sprintBranchSlug}/.shared/{repoName}/{lockDigest}/{node_modules|vendor|.venv}. lockDigest = sha256(lockfile) so a dep change forks a new shared dir and stale ones age out; identical lockfiles across all 10 worktrees share ONE install. After `git worktree add`, installSharedDepsSymlinks (new repocache/shareddeps.go) detects the package manager by manifest, installs ONCE into the shared dir under the per-repo lock (idempotent: skip if target exists), removes any real dep dir in the worktree, and `os.Symlink`s the shared target into the worktree. dev-server/ensureDeps cache (health.go) must key on the RESOLVED real path (filepath.EvalSymlinks) so 10 worktrees pointing at the same shared node_modules install + start the dev server ONCE, not 10×. The shared .shared/ dir is owned by the sprint root, excluded from per-task artifact GC, and only reclaimed when the whole sprint root is torn down. Symlinks (not hardlinks/copies) keep it one physical copy and make EvalSymlinks dedup trivial; node tolerates symlinked node_modules, Go vendoring and PHP composer/vendor tolerate symlinked vendor.

## TTL cleanup
Hook plugs into the EXISTING GC loop (gc.go gcLoop / pruneRepoWorktrees, runs every GCInterval≈1h). New config AGORA_SPRINT_WORKTREE_TTL (default 72h) in config.go alongside GCTTL/GCOrphanTTL. A per-task sprint worktree DIR is removed (`git worktree remove` + `git worktree prune` + delete its per-task local alias branch) when ALL hold: task is terminal/idle (server status query, same path shouldCleanTaskDir already uses), env root NOT in activeEnvRoots (isActiveEnvRoot, daemon.go:145), and mtime older than the sprint TTL. The shared sprint branch (origin/<sprintBranch> and any local SprintBranchFor name) is NEVER pruned — pruneWorktreeLocked's branch-delete scan (gc.go:638-657) is changed to protect sprint-* aliases and resolved sprint branches in addition to active worktree branches. The whole sprint root ({wsRoot}/{wsID}/sprint/{slug}/, including .shared/) is torn down only when the sprint itself is closed/done (a new gcDecisionSprint branch in shouldCleanTaskDir keyed off issue.sprint state). Optional fast path: an explicit POST /worktree/cleanup daemon RPC fired on task-merge so removal doesn't wait up to GCInterval — small addition, can land in slice 2.

## Bounding N
N (concurrent worktrees) == N (concurrent running tasks), already bounded by the existing taskSlotSemaphore = MaxConcurrentTasks (daemon.go:1900-1901, default 20, env AGORA_DAEMON_MAX_CONCURRENT_TASKS; activeTasks exposed on /health). The semaphore is acquired before handleTask runs and released on finish, so at most MaxConcurrentTasks worktrees are actively held at once — NOT the sprint backlog. Idle/finished worktrees beyond N are reclaimed by the TTL prune, so steady-state disk ≈ (active N worktrees, each just source delta) + (one shared .shared/ deps install per lockDigest) + (a tail of recently-finished worktrees awaiting the next GC tick). For 10 users this is 10 active source-only checkouts + 1 shared deps tree per repo, vs today's 10 full clones each with their own node_modules/vendor. The 10-user target sits comfortably under the default 20 slot cap; raise MaxConcurrentTasks if a sprint needs more parallelism than that.

## First slice (smallest shippable)
Smallest shippable slice = "shared-branch worktree, fork-model parity otherwise," NO symlinks, NO TTL, NO PR-bypass yet — prove that 10 tasks can check out and commit to ONE sprint branch. Concretely: (1) add `SprintBranch` to handler taskResponse (agent.go) + daemon Task (types.go); (2) server populates it in handler/daemon.go beside CoCodeBranch, gated on AGORA_SPRINT_WORKTREE_ENABLED + sprint.Branch set, resolved via existing SprintBranchFor; (3) add SprintBranch to WorktreeParams and the shared-branch add path (runWorktreeAddShared, detached add + per-task local alias tracking origin/<sprintBranch>) in repocache/cache.go; (4) wire the pull-before-work rebase in daemon.go runTask (mirror the existing ensureCoCodeBranch call site at 2995). This reuses the proven CoCodeBranch claim→force-branch precedent end-to-end, changes ~4 files, and is independently verifiable: claim two tasks on one sprng-enabled issue, confirm both worktrees sit on origin/<sprintBranch>, both can commit, second one rebases the first's commit. Deps still install per-worktree (slower, more disk) and accept still opens a PR — those are slices 2 (symlinks) and 3 (push-to-branch + TTL prune), each shippable on its own.

The reuse path (isGitWorktree, line 506) calls a new updateSharedWorktree: `git fetch` + `git checkout <localAlias>` + the pull-before-work rebase in step 4.
3. 3. SYMLINK shared deps (the disk bound). New file server/internal/daemon/repocache/shareddeps.go: installSharedDepsSymlinks(sprintRoot, worktreeRepoDir). Detect provider by manifest (package.json->node_modules, go.mod->vendor IF vendoring, composer.json->vendor for the SD PHP repos, requirements/pyproject->.venv). If target dir is absent, create it + run the install ONCE there under the per-repo lock; then in the worktree `os.Symlink(target, {worktreeRepoDir}/{depDir})` (after rm of any real dir). Call this from CreateWorktree after the worktree add. Add depDirs (node_modules, vendor, .venv) to gc.go GCArtifactPatterns-exclusion so artifact GC never walks into the symlink target.
4. 4. PULL-BEFORE-WORK. Add a `SprintBranch` field to daemon Task and, in daemon.go runTask right where ensureCoCodeBranch is called (line 2995-2998), branch: if task.SprintBranch != '', call new ensureSprintWorktreeSynced(env.WorkDir, task.SprintBranch, taskLog) instead. That helper, per repo under workdir: `git fetch origin <sprintBranch>` then `git rebase origin/<sprintBranch>` (fall back to `git merge --ff-only` then `git rebase` on divergence); on rebase conflict, abort the rebase, leave the worktree on the last good commit, and surface a non-fatal warning + a `sprint_sync_conflict` task annotation so the agent/human resolves rather than the daemon silently dropping commits. This runs INSIDE the per-repo lock window already held conceptually by the task slot. gitFetch in CreateWorktree (cache.go:465) already refreshes remotes, so first-claim is covered; this hook covers reuse + long-lived worktrees.
5. 5. ACCEPT = push to sprint branch, no PR. In server/internal/daemon/health.go openWorktreePR (line 869): when the worktree's upstream is the sprint branch (detect: the local alias tracks origin/<sprintBranch>, or pass sprint_branch in the /editor/open-pr request body), commit pending edits (same as today, line 881-884) then `git push origin HEAD:<sprintBranch>` directly — SKIP the `gh pr create` block (line 904-921). Return {Repo, Branch: sprintBranch, URL: ''/sprint-commit, Created:false}. discardWorktreeChanges (line 928) and gitWorktreeChanges already resolve base via resolveDiffBase → for sprint that base is origin/<sprintBranch>, which is exactly right (discard = drop MY edits, keep teammates'). No change needed there.
6. 6. EDITOR SESSION isolation. /editor/launch keys by (userID, workdir) (health.go:261). Per-task subdirs already make workdir unique per task, so 10 users on 10 task worktrees get 10 isolated code-servers for free — the GAP only bites if two users share ONE worktree, which the per-task-subdir model avoids. 7. 7. TTL CLEANUP + N bound. Add config AGORA_SPRINT_WORKTREE_TTL (default 72h) in server/internal/daemon/config.go beside the existing GC TTLs (~line 57). In gc.go pruneWorktreeLocked (line 617): keep `git worktree prune`, but for sprint worktrees do NOT delete the shared branch — change the agent-branch scan (listAgentBranches/agentWorktreeBranches, lines 696-716) to additionally protect any branch matching `sprint-*` AND the resolved SprintBranchFor names, and only `git worktree remove` a per-task worktree DIR when: its task is terminal/idle AND mtime > TTL AND the env root is not in activeEnvRoots (isActiveEnvRoot already exists). N concurrent worktrees is bounded by the existing taskSlotSemaphore=MaxConcurrentTasks (daemon.go:1900, /health exposes activeTasks) — that is the active-N cap; the TTL prune reclaims idle ones so total-on-disk stays ~= active + recently-finished, never the whole backlog.

## Risks
- CONCURRENT-INDEX / git lock contention: 10 worktrees share ONE bare repo; `git worktree add`, `fetch`, and `branch -D` all mutate the bare repo's packed-refs/config/worktrees admin dir. cache.go already serializes these with lockForRepo/WithRepoLock (cache.go:115-137, 457) — sprint paths MUST stay inside that lock. The per-worktree index (.git/worktrees/<id>/index) is independent, so working-tree edits and rebases do NOT contend; only the shared-ref mutations do. Risk is mitigated as long as ensureSprintBranch/worktree add/prune are all under the repo lock; pull-before-work fetch is per-worktree and also taken under the lock.
- PUSH races to the shared branch: 10 worktrees pushing to origin/<sprintBranch> will hit non-fast-forward rejections when teammates pushed first. Mitigation: openWorktreePR's sprint path must `git fetch && git rebase origin/<sprintBranch>` then retry push once on rejection (bounded retry, surface conflict on second failure). This is the CI model's core conflict surface — last-writer must rebase, never force-push (force-push to a shared branch would clobber teammates and is explicitly forbidden in this path).
- FILE-LEVEL concurrent edits: two humans editing the same file in different worktrees is last-push-wins at the git layer (clean), but two humans in the SAME code-server session is last-save-wins with no merge (existing behavior, health.go:257-261 comment). Per-task subdirs avoid the same-worktree case for v1; cross-worktree conflicts surface as rebase conflicts at accept time, which is the intended CI semantics, not a silent loss.
- PROD-BOX safety: ensureSprintBranch can create-and-push a missing branch off the default branch. On a daemon bound to a prod/QA box this must NEVER auto-create or push to a protected branch. Gate creation behind the sprint being explicitly configured (sprint.Branch set by a human) and refuse to create branches whose name matches main/master/release/* ; for QA-box daemons, require the branch to ALREADY exist (verify-only, no create). Direct push-to-sprint-branch (no PR) also means no PR review gate — acceptable for an integration branch but the sprint branch itself should merge to main via a real PR (the sprint-end QA + deploy flow, which already exists via SprintBranchFor/DeploySprintBranch).
- SYMLINK breakage: some tooling resolves realpath and escapes the worktree (e.g. a bundler writing into node_modules would write into the SHARED dir, corrupting all 10 worktrees). Mitigation: shared dep dirs are install-output only and treated read-mostly; if a repo's toolchain writes into node_modules at runtime, fall back to per-worktree real dir for that repo (detected by a per-repo opt-out). Lockfile-digest keying means a postinstall that mutates the tree is shared deliberately, not accidentally.
- MIGRATION reversibility: shipping behind AGORA_SPRINT_WORKTREE_ENABLED + per-sprint opt-in means the fork model stays default; if sprint mode misbehaves, unset the flag and tasks fall back to per-task agent/* branches with zero schema rollback. Old daemons that don't understand sprint_branch simply ignore the field (omitempty) and keep forking — safe across the installed-app version skew the API-compat rules require.

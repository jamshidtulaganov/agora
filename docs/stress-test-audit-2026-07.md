# Agora Stress-Test Audit — Sprint-Mode Coherence, Routing, and the QA/Docs Loops

## 1. Verdict

**The current stress-test setup is not coherent under the new rules, and the incoherence is structural, not cosmetic.** The `sprint_mode` flag the user is toggling (`project.settings.sprint_mode=true` on sd-main) is **read nowhere in the Go backend** — it is a frontend view-toggle only. Every backend decision that *should* key on it (the dev brief's "open a PR" instruction, the daemon's sprint-branch force, the squad-leader delegation, the QA smoke target) instead keys on a global env flag (`AGORA_SPRINT_WORKTREE_ENABLED`) plus *direct* issue-in-sprint membership — and that membership is never inherited by the leader-created child dev tasks where code is actually written. Layered on top, the **`sprint10` branch does not exist on the fork**, so even the machinery that *is* wired up silently degrades to the fork+PR model. The result is exactly the violation the user flagged: PR #2 (`fix/SD-145-sale-auto-calc` → `billing`, still OPEN) is a per-task PR opened while sprint_mode is on, and the sandbox QA box is wedged at `exit status 128` trying to sync a branch that was never created. Separately, the routing/ownership model is under-built: 92 of 108 sprint issues are human-member-assigned and therefore **never trigger any agent or QA path**; the "S-context" is a title string with zero backend meaning; SD-377 sits in sd-main though it belongs to sd-cs; and sd-cs has no squad, no sprint_mode, and no box, so it cannot receive that work today. Nothing about the run is currently exercising the sprint-mode contract end-to-end.

## 3. The corrected end-to-end model (one sprint, sprint_mode ON)

This is the intended flow after the fixes, with the no-PR rule made explicit and pinned to enforcement points:

1. **Sprint activation** creates the shared branch, once. When a sprint on a sprint-mode project transitions to `active` (`sprint.go` create/update), the backend (a) **rejects a blank `.Branch`** (fix #17), and (b) via a control-plane ensure-step, cuts `refs/heads/sprint10` off the fork base `billing` if absent (fix #2, placed in `DeploySprintBranch` before `performBoxSync`, **not** in the daemon). **Owner of the branch = the Agora control plane at activation**, never an agent's incidental first push. Naming: keep the explicit `sprint.branch` string ("sprint10") as the single source of truth; `sprint/<uuid>` is only the fallback for a (now-rejected) blank branch — created and fetched refs must be exactly `SprintBranchFor(sprint)` so they agree by construction.

2. **Issue → orchestration.** An issue carries its routing via `project_id` (not a title prefix). For an sd-main sprint issue owned by a human dev, the human either works it on their own box or **explicitly delegates execution to the squad** via `executor_squad_id` (fix #7) while remaining the accountable assignee. Squad assignment enqueues the leader (`is_leader_task`).

3. **Delegation inherits the sprint.** The leader creates a `todo` child dev sub-task. On child create, the **service layer inherits the parent's active sprint** into `issue_to_sprint` (fix #1) — this is the load-bearing fix. Now `GetSprintForIssue(child)` succeeds, so `daemon.go:1350` sets `resp.SprintBranch = "sprint10"` and the daemon puts the worktree on a `sprint-wt-<taskID>` alias tracking `origin/sprint10`.

4. **Commit to the ONE shared branch, no PR.** The dev agent's brief (fixed slice instruction, fix #3) and the SD Orchestrator/Developer DB instructions (fix #6) both say: *in sprint mode, commit to `sprint10`, do not branch, do not `gh pr create`*. At accept, `ensureSprintBranch` finds `origin/sprint10`, `sprintUpstreamBranch` matches the `sprint-wt-` prefix, and `pushToSprintBranch` pushes straight to the shared branch. If the branch is somehow still absent, `ensureSprintBranch` **fails the task closed** rather than falling back to a PR (fix #9). **The no-PR rule is enforced in three places after the fix:** the slice instruction (`CreateSliceAction`/`maybeRunQAOnInReview` gate on sprint context), the daemon accept path (`sprintUpstreamBranch`/`ensureSprintBranch` threaded with sprint_mode so `gh pr create` is unreachable for sprint issues), and the agent prose (DB instructions conditional). Belt-and-suspenders because the model may ignore prose.

5. **QA smokes the shared branch.** On `in_review`, `maybeRunQAOnInReview` calls `DeploySprintBranch` → converges the **project box** (sandbox) onto `sprint10` and smokes *that* integrated state. Because all sprint work lands on one branch, QA of the integrated sprint is the project box on sprint10; per-dev boxes are only for pre-integration per-task smoke. A sync failure now **blocks the verdict** (`qa:blocked`, fix #4) instead of passing against stale `billing`, and `qa_evidence` records the tested SHA + baseline (fix #15), with the last-green ref derived from the branch name (fix #16).

6. **Docs, batched.** On `qa:pass`, `auto_docs` — gated on sprint_mode (fix #10) — appends to ONE per-sprint docs branch (`docs/sprint10`) via a resolvable, single-purpose docs agent (fixes #11, #18), idempotently (fix #10's `docs:done` label). No per-sub-task MR spam.

7. **Sprint end.** The shared `sprint10` branch merges to base. *This is the open question below:* "no PR" almost certainly means "no **per-task** PR," with a single sprint-level merge/PR to `billing` at close — the sprint-end regression/deploy flow is where that lands.

**Non-sprint projects (sd-cs):** the same gates naturally keep them on the per-task branch + PR flow, since `GetSprintForIssue` returns nothing and sprint_mode is off. That asymmetry is correct and desired.

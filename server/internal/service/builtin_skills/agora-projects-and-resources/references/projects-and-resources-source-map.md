# Projects and resources source map

- `server/cmd/agora/cmd_project.go` registers project `list`, `get`, `create`, `update`, `delete`, and `status`.
- The same file registers `project resource list/add/update/remove`.
- `project create --repo` attaches `github_repo` resources during project creation.
- `project resource add` supports shortcuts for `github_repo` (`--url`, `--default-branch-hint`) and `local_directory` (`--local-path`, `--daemon-id`, `--ref-label`), or generic `--ref '<json>'`.
- `project resource update` merges shortcut edits with existing `resource_ref` so a partial edit does not clobber required fields.
- `server/cmd/server/router.go` exposes `/api/projects` plus `/api/projects/{projectId}/resources` routes.
- `server/pkg/db/queries/project_resource.sql` is the CRUD query surface for `project_resource` rows.
- `local_directory` mutations are human-gated: `IsMachineActor` (`server/internal/handler/actor_guards.go`) returns 403 for `task_token` / `cloud_pat` actors in `CreateProjectResource` / `UpdateProjectResource` / `DeleteProjectResource` (`server/internal/handler/project_resource.go`) and in `CreateProject`'s bundled-resources loop (`server/internal/handler/project.go`). `github_repo` stays machine-creatable.
- local_directory tasks additionally require on-machine owner approval: `checkLocalDirApproved` (`server/internal/daemon/local_allowlist.go`) gates `acquireLocalDirectoryLockIfNeeded` (`server/internal/daemon/daemon.go`); approvals come from `~/.agora/local-dirs.json` (written by `agora daemon allow-dir` — `server/cmd/agora/cmd_daemon.go` — and the desktop picker's `local-directory:approve` IPC) merged with `AGORA_LOCAL_DIR_ALLOWLIST`. Protected home subtrees (dot-dirs under `$HOME`, `~/Library`, `AppData`) are denied by `isProtectedHomeSubtree` (`server/internal/daemon/local_directory.go`).
- `findLocalDirectoryAssignments` (`server/internal/daemon/local_directory.go`) resolves every position-ordered row for the executing daemon: first is primary, later rows are additional roots, and symlink aliases to one real path fail closed. `acquireLocalDirectoryLockIfNeeded` validates/approves all roots and locks in canonical sorted order; `provisionLocalWorktreesForRootsAt` (`server/internal/daemon/local_worktree.go`) creates sibling worktrees when isolation is required. `TaskContextForEnv.LocalWritableDirs` reaches the runtime brief and Codex's `sandbox_workspace_write.writable_roots` managed config.
- `requireLocalDirectoryDaemonAccess` (`server/internal/handler/project_resource.go`) validates the ref's `daemon_id` on create and on any `resource_ref` update by delegating to `requireDaemonAccess` (`server/internal/handler/runtime.go`), which queries `ListAgentRuntimesByDaemonID` (`server/pkg/db/queries/runtime.sql`): no runtime rows → 400 unknown daemon_id; otherwise `canUseRuntimeForAgent` (same file) must pass for at least one row (runtime owner, workspace owner/admin, or `visibility=public`) → else 403.
- The web folder picker attaches without typing a path: `GetDaemonBrowseTarget` (`server/internal/handler/browser_proxy.go`, routed at `/api/runtimes/by-daemon/{daemonId}/browse` in `server/cmd/server/router.go`) reuses the same `requireDaemonAccess` gate, then returns the daemon's `editor_addr`/`editor_port` base (`resolveDaemonInternalAddr` / `daemonEditorBase`, `server/internal/handler/editor.go`) as `daemon_url` — a `/browser/proxy/<token>` base for cloud (`registerBrowserTarget`, membership re-checked per request by `ProxyBrowser`) or loopback for self-host; `mode:"offline"` when the machine is registered but not running. The web then lists directories via `GET <daemon_url>/editor/fs/list` (`server/internal/daemon/health.go` → `browseLocalDir`, `server/internal/daemon/fs_browse.go`), allowlisted in `browserProxyPathAllowed` as an exact path. Listing is read-only and never approves: browsable roots are `$HOME` + `loadLocalDirAllowlist()` entries, minus system roots and protected home subtrees.
- Project resources are written into `.agora/project/resources.json` for agent workdirs.
- `server/cmd/agora/cmd_project.go` also registers `project qa-manifest get/set/build` (`set` reads `--file` or stdin and PUTs the manifest JSON).
- `server/internal/handler/project_qa_manifest.go` implements `PUT /api/projects/{id}/qa-manifest` (merge-writes ONLY the `qa_manifest` key in `project.settings`; validates base_url + non-empty routes/flows/auth) and `POST /api/projects/{id}/qa-manifest/build` (queues the lead agent's derivation task).
- `maybeEnqueueQAManifestBuild` fires the background build on project create (`server/internal/handler/project.go`) and on the first code-resource attach (`github_repo` or `local_directory`, `server/internal/handler/project_resource.go`), guarded: agent lead + source present + no existing `qa_manifest`.
- Project evidence retrieval: `server/internal/repoindex/cache.go` persists a private fingerprinted term corpus; `PackRootsCached` scores all attached roots without rereading their full contents on unchanged tasks. `server/internal/daemon/repoindex.go` runs the cold build before `StartTask` and injects the bounded evidence pack for every cold project issue.
- `server/internal/handler/slice_action.go` (`sliceActionQAManifestContext`) injects the manifest — including `known_issues` and `notes` — into every QA slice instruction and every daemon claim (`server/internal/handler/daemon.go`).
- Knowledge base: `knowledge_item` rows (migration `146_knowledge_item`, queries `server/pkg/db/queries/knowledge_item.sql`) are compiled into the `<slug>-kb` skill by `server/internal/service/knowledge_compile.go` (`RecompileKB`, keyed by resolved KB name; splices only the `agora:kb:items` marker region). Agent ` ```knowledge-items``` ` comment blocks are parsed by `server/internal/service/knowledge_item.go` (`CaptureKnowledgeItems`), wired from `server/internal/handler/comment.go` and `createAgentComment` in `server/internal/service/task.go` (pre-expansion content).
- `server/internal/handler/issue.go` (`maybeEnqueueKnowledgeCapture`) fires the capture on a genuine ->done transition; `server/internal/handler/knowledge_synth.go` (`resolveKBSynthesizer`) finds/auto-provisions the "KB Synthesizer" agent and stamps its UUID (the ingest trust anchor). Human review CRUD: `server/internal/handler/knowledge_item.go` (`/api/projects/{id}/knowledge/items`, `/api/knowledge-items/{itemId}`; mutations require a human actor).
